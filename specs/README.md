# Project Specifications (AI Quick Start)

- This repository manages Websoft9 marketplace product production and maintenance tasks. Existing platform data and issue workflows are core business assets.
- The business positioning and scope are defined in [`business-positioning.md`](business-positioning.md).
- GitHub Actions connects to AWS through OIDC; see [`cloud-connector.md`](cloud-connector.md).
- Generate ready-to-load local config at `.secrets/<target>.env` for any cloud plus `contentful`, `wecom` and `websoft9` with `make cloud-configure cloud=all`; `mk --env-file` and `make cli cloud=aws` load one file. See [`cloud-connector.md`](cloud-connector.md) for targets and secret fields.
- Product master data, the shared AWS listing template and `mk offer build/plan` rendering rules are defined in [`marketplace-product-content.md`](marketplace-product-content.md).
- For the paused product-file Issue workflow and its replacement by catalog/CLI flow, including the approved GitHub Actions apply workflow, see [`marketplace-offer-update-workflow.md`](marketplace-offer-update-workflow.md); Odoo preparation is in [`odoo-first-publication.md`](odoo-first-publication.md).
- Per-application offer wording exceptions, such as an open-source edition that is not called "Community Edition", are defined in [`app-offer-special-cases.md`](app-offer-special-cases.md).
- Wave-based AWS logo/image refresh uses fixed URLs and the normal revision/hash-protected plan/apply executor through `--assets`, without image SHA/version staging. `offer-update.yml` selects Product information (default) or Asset per run. Template `baseUrl`, explicit refresh, approval, submit-only defaults and optional field read-back are described in [`offer-assets.md`](offer-assets.md).
- To export English Contentful application fields for the current `product_en.json` applications, see [`catalog-pull.md`](catalog-pull.md). To validate the catalog and confirm only selected fields changed, use `mk catalog verify`. To write reviewed metadata to Contentful drafts or publish it, see [`catalog-push.md`](catalog-push.md).
- Generate the local marketplace code matrix with `mk offer-codes gen` (AWS, Aliyun China, Alibaba Cloud International, Azure `websoft9inc`, `azure-vmlab`, Huawei Cloud China `huaweiyun`, International `huaweicloud` and Google Cloud `googlecloud`), using live store facts or `--inventory` store JSON snapshots. Its shared per-product app-match/decision report, format and maintenance commands are described in [`offer-codes.md`](offer-codes.md). Both Azure publishers write `productID.azure`, replacing only their own codes and preserving the other publisher. Google Cloud is an additive optional matrix column. Offer variants are declared through `multiOffers`, not per-code labels.
- Query public image products by store/provider with `mk store products --platform <cloud|all> --json` or `mk offer list` (AWS, Aliyun China, Alibaba Cloud International, Azure `websoft9inc`, Azure VMLab, Huawei Cloud China, International and Google Cloud), independently of application mappings. Both Huawei sites and Google Cloud use verified public storefront facts, not authenticated seller OpenAPI; no account credentials or OIDC are needed for these read-only paths. The shared collection layer, JSON contract, credentials, ownership evidence and partial-failure rules are in [`store-products.md`](store-products.md).
- Store queries, matrix generation and `offer resolve` share explicit public-scope inventory input. `offer-update.yml` snapshots store facts before resolving; plan/apply keep live revision checks. See [`store-products.md`](store-products.md) and [`marketplace-offer-update-workflow.md`](marketplace-offer-update-workflow.md).
- Shared deterministic identity rules for `offer-codes gen` and `offer resolve`/Apply are in [`application-matching.md`](application-matching.md): normalized trademarks, Apache-prefix fallback, conservative ID fallback and first-appearance selection, with decision evidence.
- Shared OS names, displays, aliases and version-example metadata live in `config/os-catalog.json`; runtime loading/validation, offer consumers and the family-only compatibility contract are in [`os-catalog.md`](os-catalog.md).
- Files such as `aliyun.json`, `aws.json`, `azure.json`, `huawei.json`, and `qcloud.json` contain existing task data. Check downstream consumers before editing and preserve their schemas.
- AI collaboration rules are in the root `AGENTS.md`; reusable workflows are in `.agents/skills/`.
- Reusable automation scripts live in the root `ci/` directory.
- Business commands use the `mk` CLI in `cli/`, separate from development `make` targets; `make cli` creates `.venv`, installs the CLI, and enters the `mk` command shell. Run `make test` for the main and CI test suites, or `make test-main` / `make test-ci` for one suite.
- To list marketplace product versions from cloud APIs, see [`marketplace-versions.md`](marketplace-versions.md). The initial implementation supports Aliyun China.
- Marketplace title/summary version extraction rules are in [`marketplace-version-extraction.md`](marketplace-version-extraction.md).
- Marketplace platform URL templates, Websoft9 store homepages, supplier IDs/UIDs, per-platform product artifacts, search URL prefixes, and code routing live in `config/marketplace.json`. Shared data sources live in `config/sources.json`: each entry under `sources` contains a non-empty `summary` describing the dataset and a `url` read by consumers. The source keys are `catalog`, `versions`, `category`, and `offer-codes`. Consumers use the published offer-code matrix from `sources.offer-codes.url`; generation and local editing stage under the ignored `data/.work/offer-codes/` directory. Application catalog, version baseline, and category URLs are `sources.catalog.url`, `sources.versions.url`, and `sources.category.url`. The site can override the sources configuration path with `MK_SOURCES_CONFIG_PATH`; existing per-source URL overrides remain unchanged. Per-application offer rendering settings live in `data/listing/app-special-cases.json`. The artifact, generation and validation details are in [`offer-codes.md`](offer-codes.md).
- The static Marketplace dashboard lives in `site/` (Astro): `/` is the overview, `/apps` is the application list, `/apps/<key>` is the application detail page, and `/products` is the per-cloud product list; pages read the marketplace data sources at build time.
- The `/products` page uses horizontal platform tabs. It reads each platform's `productsArtifact` generation report from `config/marketplace.json` in parallel, falls back to the offer matrix from `config/sources.json` when no artifact is configured or readable, and uses the catalog for application trademarks. Platforms without a product URL template are shown as an explicit "no data" tab instead of being omitted. The site derives its platform list from `config/marketplace.json`: every entry with a `urlTemplate` is included, so newly configured platforms such as `huaweiyun` and `huaweicloud` need no site-side allowlist change. Each tab shows product totals and a searchable/sortable list with product title (the short description is shown as a hover tooltip, with the product code and copy control beneath), stacked application ID/trademark (trademark links to the catalog `websiteurl` when available), and a per-row vertical-dots menu with icon actions: update the offer, update application metadata, and search the platform marketplace using the platform's `searchUrlPrefix` plus the application trademark. The toolbar can export all products of the current tab as a Markdown table with English headers. Build-time requests are memoized; filtering, sorting and export run in the browser only.
- Start the site in the foreground with `make site` (or `cd site && npm start`). The command keeps Astro attached to the terminal and automatically selects the next free port when 9001 is occupied; current custom `--port`/`PORT` values and other Astro flags are forwarded, while `--background` is ignored.
- Application detail pages read use cases and keywords directly from `product_en.json`; they no longer depend on `data/app-metadata.json`.
- To query Aliyun products and check application image versions, use [`aliyun-product-freshness`](../.agents/skills/aliyun-product-freshness/SKILL.md).
- The scheduled and manually triggered multi-cloud product freshness entry point is documented in [`product-freshness-workflow.md`](product-freshness-workflow.md).
- The project OpenCode MCP configuration is `.opencode/opencode.json`: GitHub and Context7 use remote services, while Playwright is launched locally with `npx`. The GitHub token must remain outside the repository in the user's OpenCode config directory; Node.js must be available to the OpenCode service process.
- Batch AppStore detail screenshots through GitHub Actions and S3 are defined in [`appstore-screenshots.md`](appstore-screenshots.md).
